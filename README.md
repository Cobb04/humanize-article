# Humanize Article

把“太像 AI 写的”的中文科技或商业文章，改回有人在讲故事的样子。

这个 Codex Skill 不负责把文章改得更像一份大纲，而是先诊断原文，再用场景、节奏、具体数字和贯穿全文的核心意象重写。

## 适用场景

- 文章过于 AI 感、缺乏文学性
- 章节结构太整齐，像 PPT 或报告
- 评价词太多，缺少具体场景和动作
- 比喻只出现一次，转折词和总结句过密
- 结尾过于干净，缺乏余味

## 使用

```text
$humanize-article

请把下面这篇文章改得不那么像 AI，保留事实和核心观点：
……原文……
```

也可以指定方向：

```text
使用 $humanize-article 重写这篇商业分析。
保留数据，减少小标题，增加叙事感，结尾留一点不确定性。
```

## 工作方式

1. 扫描原文的七个 AI 写作特征：结构外露、解释过度、情感叙述、句式单调、比喻装饰、转折机械、结尾过净。
2. 针对命中的问题定向改写，而不是套一套固定模板。
3. 全文通读，检查长短句节奏、核心比喻是否承重、结尾是否保留开放性。
4. 保留事实、数字、引用和作者真正的判断，不用“文学性”掩盖事实改写。

## 核心原则

> AI 在执行大纲，人在讲故事。

- 用场景和动作呈现评价，不直接宣布“重要”“危险”“聪明”。
- 用具体数字替代抽象定性。
- 把悖论前置，让读者先遇到问题，再跟着文章寻找解释。
- 删除不必要的“首先、其次、然而、综上所述”。
- 让一个核心意象贯穿全文，而不是每段换一个比喻。
- 不给每一段强行下结论，给读者留一点参与推理的空间。

## 安装

```bash
git clone https://github.com/Cobb04/humanize-article.git
cp -R humanize-article/humanize-article ~/.codex/skills/
```

安装后的 Skill 文件：

```text
~/.codex/skills/humanize-article/SKILL.md
```
