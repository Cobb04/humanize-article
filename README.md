# Humanize Article

有些文章像会议室：门牌、流程、总结都很齐，进去以后却没人说人话。

`humanize-article` 专门把中文科技和商业文章从会议室里领出来。它不负责把句子变得“更像一份大纲”，而是找出那些暴露 AI 痕迹的地方，再用场景、动作、具体数字和一点留白，把文章还给读者。

## 你可以这样叫它

```text
$humanize-article

请把下面这篇文章改得不那么像 AI，保留事实和核心观点：
……原文……
```

也可以加一句编辑意见：

```text
使用 $humanize-article 重写这篇商业分析。
保留数据，少用小标题，增加叙事感，结尾留一点不确定性。
```

它会先读完整篇文章，再动笔。事实、数字、引用和作者真正的判断留在桌面上；“首先我们来看”“值得注意的是”和“综上所述”如果只是来报到，通常会被请回去。

## 它在抓什么

文章不需要七个问题全中。命中哪几个，就修哪几个。

| AI 痕迹 | 改写动作 |
| --- | --- |
| 结构外露 | 不宣布下一章要讲什么，让故事自己往前走 |
| 解释过度 | 比喻说完就停，把理解权还给读者 |
| 情感只写在脸上 | 用数字、场景和动作展示，不替读者尖叫 |
| 句子排队太整齐 | 长段铺垫，短句落地，偶尔留一个问句 |
| 比喻用完即弃 | 选一个核心意象，让它在不同段落继续干活 |
| 转折词机械换班 | 删掉“然而”“但是”，让上一段把问题递过来 |
| 结尾干净得像酒店退房 | 留一点未解决的张力，让故事别急着关灯 |

## 几个判断标准

“这是一个危险的处境”不如“20 美元进来，30 美元出去”。

“接下来我们来看 Harness”不如把一个陌生程序员直接丢进陌生公司，看他能不能开工。

“由此可见，Cursor 建立了护城河”也不如承认：护城河还没修完，对手已经在河对岸量木头了。

这不是为了把每句话都写成段子。幽默只负责开门，准确负责让读者留下来。

## 改完要检查什么

从头再读一遍，问三个问题：

- 最长段和最短段之间有没有呼吸，而不是一排等长砖头？
- 核心比喻有没有在至少三个地方帮助读者理解新东西？
- 结尾有没有留下尚未落地的东西？如果最后只剩“因此、综上、由此可见”，大概率还没下班。

改写不会替你发明事实，也不会用“文学性”给数据换一件漂亮外套。原文没有的数字，不能因为它读起来很顺就凭空出现。

## 安装

```bash
git clone https://github.com/Cobb04/humanize-article.git
cp -R humanize-article/humanize-article ~/.codex/skills/
```

安装后的 Skill 文件：

```text
~/.codex/skills/humanize-article/SKILL.md
```

## 目录

```text
.
├── README.md
└── humanize-article/
    └── SKILL.md
```

更完整的诊断信号、Before/After 示例和全文检查清单，都在 `humanize-article/SKILL.md` 里。README 只负责告诉你门在哪，真正的编辑工作还得进屋。
